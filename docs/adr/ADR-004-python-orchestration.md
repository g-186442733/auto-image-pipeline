# ADR-004: 纯 Python 脚本编排，不使用工作流引擎

## Status
Accepted

## Date
2026-04-17

## Context

项目需要将多个处理步骤串联起来：竞品数据采集、图片分析、提示词生成、图片生成、质检、标签标注。

常见的做法是使用工作流引擎（如 n8n、Airflow、Prefect）来可视化编排这些步骤。然而：

1. 老板明确要求不使用 n8n
2. L2 阶段编排逻辑相对简单，步骤数量有限
3. 团队对 Python 最为熟悉，现有系统（osint-station、字幕翻译等）均使用 Python 脚本

## Decision

采用**纯 Python 脚本编排**，每个步骤是一个独立的 Python 模块/脚本，通过主控脚本或命令行手动调用。

不引入 n8n、Airflow、Prefect 或其他工作流引擎。

## Consequences

### Positive
- 完全控制执行逻辑，无框架黑盒
- 调试方便：Python 调试工具链成熟（pdb、IDE 断点、print 调试都可用）
- 与现有系统（osint-station 等）技术栈一致，无需学习新工具
- 无额外服务依赖，部署简单
- 代码审查和版本管理直接用 Git，无需处理工作流引擎的导出格式

### Negative
- 无可视化编排界面，流程图需另外维护（如本文档）
- 复杂分支逻辑、错误重试、并行执行需要手写，不如工作流引擎开箱即用
- L3+ 阶段如果引入事件驱动，Python 脚本的局限性会逐渐显现，届时需要重新评估

## Alternatives Considered

| 方案 | 优点 | 缺点 | 未选原因 |
|------|------|------|----------|
| n8n 自部署 | 可视化拖拽，非技术人员友好 | 老板明确拒绝；需要维护额外服务 | 明确排除 |
| Airflow | 功能强大，DAG 可视化 | 配置复杂，学习成本高，L2 阶段过重 | 超出当前阶段需求 |
| Prefect | 现代化，Python 原生，比 Airflow 轻 | 仍需引入新依赖和概念，团队不熟悉 | 没有明显优于纯 Python 的收益 |
