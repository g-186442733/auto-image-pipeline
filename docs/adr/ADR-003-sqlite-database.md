# ADR-003: 数据库选择 SQLite

## Status
Accepted

## Date
2026-04-17

## Context

项目需要持久化存储以下数据：
- 竞品分析结果（ASIN、BSR、评分、主图 URL 等）
- 图片生成任务记录（提示词、生成参数、输出路径）
- 标签标注结果（意图标签、角色标签、视觉特征标签）

L2 阶段为**单用户本地运行**，不存在多用户并发写入场景。LLM 辅助分析时，希望能直接查询数据库而无需额外配置。

## Decision

选择 **SQLite** 作为 L2 阶段的数据库，不使用 PostgreSQL 或 MySQL。

数据库文件存放于项目目录下：`data/pipeline.db`。

## Consequences

### Positive
- 零运维：无需安装数据库服务，无需管理连接池、用户权限
- 文件即数据库：整个数据库是一个文件，方便备份、迁移、分享
- LLM 可直接查询：opencode 等工具可以通过 sqlite MCP 直接读写，无需额外配置
- Python 内置支持：`sqlite3` 模块无需安装依赖

### Negative
- 单写者限制：同一时刻只能有一个进程写入，L2 单用户场景不是问题，但 L3+ 并发时需迁移
- 升级代价：L3 阶段引入并发或多用户后，需迁移到 PostgreSQL，存在一次性迁移成本
- 不适合大数据量：数百万条记录以上性能开始下降（当前阶段不会触及此限制）

## Alternatives Considered

| 方案 | 优点 | 缺点 | 未选原因 |
|------|------|------|----------|
| PostgreSQL | 生产级并发，功能完整 | 需要安装服务，配置复杂，L2 阶段杀鸡用牛刀 | 超出当前阶段需求 |
| MySQL | 成熟稳定，广泛使用 | 同 PostgreSQL，运维成本高 | 同上 |
| 纯 JSON 文件 | 最简单，人类可读 | 无事务保证，并发写入易损坏，查询困难 | 缺乏结构化查询能力，无法支撑标签分析 |
