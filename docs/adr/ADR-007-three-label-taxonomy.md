# ADR-007: 三层标签体系设计

## Status
Accepted

## Date
2026-04-17

## Context

路线图最初定义了**双层标签体系**：意图标签（表达图片想传达的购买动机）+ 图片角色标签（表达图片在详情页中的功能定位）。

在实际设计过程中，发现仅靠意图和角色两个维度无法精确描述图片的视觉特征（如色调、构图风格、视觉语言），而这些特征是 AI 提示词生成的直接输入。因此将体系扩展为三层。

> **注意**：当前代码实现中使用了不同的命名约定（如 `INT_HERO` 等面向图片类型的意图标签，`ROLE_BG` 等面向图层角色的标签）。本 ADR 记录的是**路线图设计层面的原始分类体系**。代码命名与本 ADR 的对齐是一个待完成的未来任务。

## Decision

采用**三层标签体系**，三层标签正交设计，可任意组合：

### 第一层：意图标签（6 个）

描述图片希望激发的购买动机。

| 标签 ID | 含义 |
|---------|------|
| INT_01 | 性价比导向——强调物超所值、实惠 |
| INT_02 | 高端质感导向——强调品质、档次、工艺 |
| INT_03 | 便捷效率导向——强调省时、易用、方便 |
| INT_04 | 专业性能导向——强调专业级参数、技术优势 |
| INT_05 | 情绪审美导向——强调美感、情绪共鸣、生活方式 |
| INT_06 | 礼赠身份导向——强调送礼价值、身份象征 |

### 第二层：图片角色标签（7 个）

描述图片在产品详情页中承担的功能角色。

| 标签 ID | 含义 |
|---------|------|
| ROLE_01 | 主图——白底产品图，Amazon 主搜索结果图 |
| ROLE_02 | 环境图——产品在使用场景中的展示 |
| ROLE_03 | 痛点图——呈现目标用户的问题或痛苦 |
| ROLE_04 | 解决图——展示产品如何解决痛点 |
| ROLE_05 | 对比图——与竞品或旧方案的对比 |
| ROLE_06 | 细节图——产品局部特写、材质、工艺 |
| ROLE_07 | 信任图——证书、用户评价、数据背书 |

### 第三层：视觉特征标签（动态扩展）

描述图片的视觉语言，直接用于生成 AI 提示词。命名约定：`COLOR_*`、`LAYOUT_*`、`STYLE_*`。

示例：
- `COLOR_WARM`、`COLOR_COOL`、`COLOR_NEUTRAL`
- `LAYOUT_CENTER`、`LAYOUT_RULE_OF_THIRDS`、`LAYOUT_FLAT_LAY`
- `STYLE_MINIMALIST`、`STYLE_LIFESTYLE`、`STYLE_STUDIO`

视觉特征标签集合随项目积累持续扩展，不在本 ADR 中固化完整列表。

## Consequences

### Positive
- 精准描述图片的多个维度属性，三层标签正交，可灵活组合（如"高端质感 + 细节图 + 极简风格"）
- 支持交叉分析：可以统计某类意图下哪些角色转化率更高
- 视觉特征标签直接映射到 AI 提示词关键词，减少中间转换损耗
- 体系可扩展：新增标签不影响现有标注

### Negative
- 标签维护成本：三层体系比单层复杂，需要维护标签定义文档
- 标注一致性：不同人对同一图片的标注可能存在分歧，需要标注规范和培训
- 代码层面的命名对齐尚未完成，当前实现与本 ADR 定义的标签 ID 不完全对应

## Alternatives Considered

| 方案 | 优点 | 缺点 | 未选原因 |
|------|------|------|----------|
| 单层平铺标签 | 最简单，无需理解层级关系 | 标签爆炸，难以管理，无法支撑结构化分析 | 缺乏分析价值 |
| 两层（仅意图 + 角色） | 路线图原始方案，概念清晰 | 视觉特征信息缺失，AI 提示词生成质量受限 | 视觉特征层是提示词生成的必要输入 |
