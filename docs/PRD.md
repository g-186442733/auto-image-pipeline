## 1. 产品概述

### 1.1 产品定位

面向跨境电商卖家（主要为 Amazon 卖家）的 AI 驱动商品图片设计服务平台。系统将"看市场 → 出设计 → 拿结果 → 沉淀结论"四步循环自动化，逐阶段从人工辅助升级为系统自主决策。

### 1.2 核心价值主张

| 对比维度   | 传统设计师  | 本平台                      |
| ---------- | ----------- | --------------------------- |
| 出图依据   | 经验 + 感觉 | 基准库 + A/B数据 + 品牌画像 |
| 迭代速度   | 每单数天    | 自动质检、不合格自动重出    |
| 数据积累   | 不系统      | 结构化沉淀，越用越准        |
| 品类规律   | 个人经验    | 跨客户品类结论库            |
| 品牌一致性 | 靠人记      | 品牌画像卡驱动              |

### 1.3 核心飞轮模型

```
看市场 → 出设计 → 拿结果 → 沉淀结论
   ↑                              ↓
   ←──────── 数据回流 ────────────←
```

**三个数据引擎**：

- **引擎A**：Amazon 公开数据（市场要什么 — 赢的设计长什么样）
- **引擎B**：客户 A/B 测试数据（什么设计有效 — 哪个方案转化率高）
- **引擎C**：客户品牌画像（这个客户适合什么 — 品类级精准到品牌级）

## 2. 用户与场景

### 2.1 目标用户

| 用户类型     | 描述                          | 核心需求                   |
| ------------ | ----------------------------- | -------------------------- |
| Amazon 卖家  | 中小型跨境电商，月销 $5k-$50k | 提升 CTR/CVR，降低设计成本 |
| 品牌出海团队 | 有品牌意识，注重视觉一致性    | 品牌化表达，多品类扩展     |
| 服务代理商   | 代运营，管理多个客户账号      | 批量出图效率，数据复用     |

### 2.2 核心使用场景

1. **新品上线**：快速生成符合品类视觉基准的首套图片（1主图+7副图+Basic A+）
2. **CTR 优化**：基于 A/B 数据自动生成改版方案，主动推荐胜出变量
3. **品牌升级**：结合品牌画像与市场基准，系统化更新视觉资产
4. **批量扩品**：同一品牌新 SKU 快速复用品牌画像 + 品类结论出图
5. **趋势响应**（L5）：系统自主发现趋势变化，主动通知卖家并推送更新方案

## 3. 四阶段产品路线图

### 3.1 阶段一：AI+数据驱动（0—3个月）

**编排等级**：L2 多工具并行  
**获客目标**：5个付费客户  
**定价**：入门包 ¥3,000-8,000/单

**核心能力**：

- Amazon Top 50 自动抓取 + AI批量标注（Gemini/GPT-4o）+ 人工复核
- 品类视觉基准库（每两周快照）
- 竞品分析模块（Listing/评论/Q&A/图片结构/价格带/推广节奏）
- 三层标签体系：视觉特征标签 + 意图标签（INT_01~06）+ 角色标签（ROLE_01~07）
- 客户提资清单（5组必问 + 5组建议）
- 出图标准流程（11步：提资→画像→brief→slot_plan→生成→精修→QA→交付→反馈→回收）
- 品牌画像卡（第一次合作建立，持续更新）
- A/B 数据记录（CTR/CVR + 设计变量标签）
- 品类假设 → 品类结论进化路径

**五个沉淀物**：

1. Amazon Top20 基准库
2. A/B 对比数据
3. 品类假设/结论库
4. 标准化标签数据表（三层：视觉+意图+角色）
5. 客户品牌画像库

**关键约束**：

- 每张图只有一个主意图（INT_01~06），副意图可空
- 一图一主角色（ROLE_01~07）
- 每轮修改只改一个关键变量
- 交付前必须过 QA Gate

---

### 3.2 阶段二：事件驱动流水线（3—6个月）

**编排等级**：L3 流水线（Pipeline + Fan-out/Fan-in）  
**获客目标**：20+客户，复购率 >40%  
**定价**：¥500-2,000/月订阅  
**获客渠道**：案例拆解内容 + 转介绍激励 + 平台入驻

**核心能力**：

- 采集→标注→入库→报告 全自动 Pipeline 串联
- 出图前决策辅助：客户输入触发三引擎（A+B+C）Fan-out 并行查询
- Fan-out 查询：同时检索基准库 + 品牌画像 + 历史A/B数据，汇总生成推荐报告
- 自动数据回收：上线后 2 周自动触发结果追踪流程
- 扩展竞品分析模块5-6（价格带分析 + 时间序列推广节奏分析）
- 多品类并行服务（不只限于单一品类）
- 品牌画像自动更新（A/B结果自动回流）
- 内容获客系统（品类报告作为获客钩子）

**新增编排动作**：

- 事件驱动触发：新 ASIN 录入 → 自动启动竞品分析
- 三引擎并行：一键触发引擎A/B/C同时查询，3秒内返回推荐 brief
- 结果追踪：上线时间戳记录 → 14天后自动提醒回收数据

---

### 3.3 阶段三：Loop 闭环（6—12个月）

**编排等级**：L4 Loop 闭环  
**获客目标**：50+活跃客户  
**定价**：¥5,000/月  
**获客渠道**：SEO + 品类报告引流 + 自动化线索培育

**核心能力**：

- 出图 → 自动质检 → 不合格自动重出的完整 Loop
- **LoRA 品牌锁**：为每个品牌训练专属 LoRA 模型，确保生成图高度吻合品牌风格
- 置信度评分驱动自动决策（是否需要人工干预）
- 反馈数据自动回流更新品类库和品牌画像
- 自动质检系统（QA Gate 自动化）：产品准确性 + 平台规范 + 缩略图可读性 + 套图一致性
- 品类知识引擎：跨客户匿名化归纳品类结论，置信度打分体系
- 客户品牌表+产品表拆分（阶段一扁平表升级为三级结构）
- 自动修改执行：客户反馈自动转译为变量修改指令

**Loop 核心流程**：

```
出图初稿 → 自动 QA 评分 → [达标] → 交付
                         ↓ [不达标]
                    自动调参重出 → 自动 QA 评分（循环）
```

**品牌锁技术栈**：

- LoRA 训练数据：历史胜出图 + 品牌画像卡中的视觉偏好字段
- 触发条件：品牌合作满 10 单且 A/B 数据 ≥ 5 组
- 输出：品牌专属 LoRA 权重文件，集成进生成 Pipeline

**L4 实施状态**（与 SYSTEM_SPEC §8 一致）：

| 能力项                              | 当前状态     | 备注                                                               |
| ----------------------------------- | ------------ | ------------------------------------------------------------------ |
| 自动 QA Loop（QA Gate + 自动重出）  | ✅ L4 已实现 | `qa_gate.py` 581行实现5道门；`orchestrator.py:488` 自动重出最多3次 |
| 置信度评分驱动决策                  | ✅ L4 已实现 | `confidence_routing.py` 实现；ConfidenceRouter 驱动自动/人工分流   |
| 品牌 LoRA 训练流水线                | ✅ L4 已实现 | `lora_trainer.py` 完整流水线；训练→测试→集成 Pipeline 已就绪       |
| **品牌 LoRA 生产化（≥3 客户在用）** | ❌ 未实现    | **L5 跃迁的硬性前置条件**（详见 L5_REQ §1.1）                      |
| 品类知识引擎（跨客户匿名化）        | ✅ L4 已实现 | `knowledge_anonymizer.py` 实现跨客户脱敏归纳；置信度打分体系完成   |
| 反馈数据自动回流                    | ✅ L4 已实现 | `feedback_loop.update_brand_profile_from_results()` 已实现         |

### 3.4 阶段四：自主决策（12个月+）

**编排等级**：L5 自主决策  
**获客目标**：200+客户  
**定价**：SaaS 自助平台，获客成本趋近零  
**获客渠道**：行业报告 + SaaS 自然流量 + 战略合作

**核心能力**：

- **趋势预测引擎**：基于 12 个月历史数据时序分析，自主发现品类视觉趋势变化
- 系统自主发现问题 → 自动通知客户 → 自动生成新方案 → 自动 A/B 测试 → 结果自动回流
- **品类级 LoRA**：跨客户脱敏训练，形成品类通用视觉先验
- **SaaS 自助平台**：卖家自助录入产品，系统全自动出图
- 数据库从 SQLite 迁移至 PostgreSQL（支持高并发、复杂查询）
- 多平台支持：Amazon + 站外广告 + 独立站
- 自动 A/B 测试调度（不需人工触发）
- 竞品趋势监控：自动检测 Top 卖家主图更换，触发更新建议

**自主决策流程**：

```
趋势检测 → 变化识别 → 通知卖家 → 自动出方案 → 自动A/B → 结果回流 → 更新结论库
     ↑                                                              ↓
     ←─────────────────── 飞轮自转 ──────────────────────────────←
```

## 5. 非功能需求

### 5.1 性能

| 指标           | 阶段一~三目标  | 阶段四目标          |
| -------------- | -------------- | ------------------- |
| 三引擎查询响应 | < 5秒          | < 2秒               |
| QA Gate 评分   | < 30秒/张      | < 10秒/张           |
| 数据库并发     | SQLite，单用户 | PostgreSQL，50+并发 |
| 基准库快照     | 每两周手动触发 | 自动定时执行        |

### 5.2 数据安全

- 客户 A/B 数据严格隔离，不跨客户泄露原始数据
- 品类 LoRA 训练使用脱敏数据，不包含客户身份标识
- 品牌画像卡访问需客户授权

### 5.3 数据库

- **阶段一~三**：SQLite + SQLAlchemy ORM，`create_all()` 建表
- **阶段四**：迁移至 PostgreSQL（保持 SQLAlchemy ORM 层不变）

### 5.4 可扩展性

- 标签体系：视觉层尽量稳定，意图层先粗后细，只加不改
- 所有数据管道输出统一元数据字段：`timestamp`, `source`, `topic_tags`, `relevance_score`
- Prompt 资产结构化存储，支持变量粒度复用

## 6. 标签体系规范

### 6.1 意图标签（INT）

| 标签代码 | 标签名       | 购买动机                         |
| -------- | ------------ | -------------------------------- |
| INT_01   | 性价比导向   | 用更低成本买到够用且不差的产品   |
| INT_02   | 高端质感导向 | 想买起来更高级、更像品牌货       |
| INT_03   | 便捷效率导向 | 想省事、轻便、快速解决问题       |
| INT_04   | 专业性能导向 | 更在意参数、能力、效果、专业可信 |
| INT_05   | 情绪审美导向 | 被风格、氛围、颜值吸引           |
| INT_06   | 礼赠身份导向 | 想送人、体面、有仪式感           |

**规则**：主意图 1 个（必填），副意图可空，置信度 1-5，必须填写 `intent_reason`

### 6.2 图片角色标签（ROLE）

| 标签代码 | 标签名 | 主要作用                           |
| -------- | ------ | ---------------------------------- |

| ROLE_04  | 解决图 | 展示使用产品后痛点被解决的结果     |
| ROLE_05  | 对比图 | 展示使用前后差异或与竞品差异       |
| ROLE_06  | 细节图 | 展示材质、工艺、参数、功能细节     |
| ROLE_07  | 信任图 | 展示认证、评价、数据、背书信息     |

## 11. 贯穿始终铁律（10 条）

1. **循环从第一天就完整转** — 即使手动，也要跑完"看市场→出设计→拿结果→沉淀结论"全循环
2. **标签体系从第一天就统一** — 视觉层尽量稳定，意图层先粗后细，只加不改
3. **AI+人工双重标注从第一天就建立** — AI 做初筛，人工做终审，校准分数反哺 AI
4. **每个项目都记数据，无一例外** — 即使客户不配合回传，也用 Amazon 排名变化等替代数据
5. **人工精修环节永远不能省** — AI 生成是起点不是终点，精修保证专业度
6. **先打穿一个品类，再扩张** — 单品类做到有底气的结论后再横向复制
7. **每个品牌一张画像卡** — 从首次合作建立，持续更新，驱动生成和质检
8. **每个阶段必须有明确获客策略** — 不能只做交付不做增长
9. **编排脚本输入输出必须 JSON 标准化** — 层间通信统一格式，便于调试和扩展
10. **Loop 闭环必须有退出条件** — 重出最多 2 轮，仍不达标则转人工审核

## 12. 阶段详细补充

### 12.1 阶段二补充：Fan-out 三引擎详细流程

```
新项目录入系统 → 自动触发（事件驱动）
  ├─→ 引擎A：品类 Top 100 设计特征分布
  ├─→ 引擎B：同品类已验证最优方案
  └─→ 引擎C：客户历史偏好 + 禁忌（品牌画像）
        ↓ 自动汇总
  → 自动生成 1 页 PDF 推荐报告（含 🟢🟡🔴 信号灯）
```

### 12.2 阶段二补充：半自动数据回收 4 种方式

1. 客户直接提供 CTR/CVR 数据（理想情况）
2. 每月定期收集（标准流程）
3. 图片回收工具包（客户只需截图，系统解析）
4. 实验结束时主动询问

### 12.3 阶段二补充：竞品分析 6 模块

1. 品类 Top 100 设计特征
2. 价格区间视觉差异
3. 主图 vs 副图转化对比
4. 评论图分析（消费者语言）
5. A+ / EBC 结构对比
6. 季节性视觉变化

### 12.4 阶段二补充：内容获客 SOP

每周 1 篇拆解文（微信/小红书）→ 展示 AI+人工流程 → 引流到私信咨询 → 转化为订阅客户

### 12.5 阶段三补充：LoRA 品牌锁完整训练流程（5 步）

1. 从客户历史项目筛选 CTR/CVR 高于均值的设计，提取 20-50 张
2. 品牌画像调性关键词作 trigger word（如 `techminimal_brand_x`）
3. Flux LoRA 微调（Replicate/fal.ai 或本地 RTX 4090）
4. 生成 10 张测试图 → 人工评审 → 客户确认
5. 每累积 10 个新项目后更新一次权重

### 12.6 阶段三补充：质检闭环详细逻辑

```
LoRA 生成 4 张候选图
  → 多模态 AI 自动评估（五层理解 + 一致性）
  → 每张图 0-100 质检分
  → > 80：进入交付队列
  → 60-80：自动微调参数重出（CFG ± 0.5 / 风格强度 ± 10%）
  → < 60：转人工审核
  → 重出最多 2 轮，仍不达标则转人工
```

### 12.7 阶段三补充：五层图像理解框架（质检评分维度）

1. **物体层** — 能判断这是什么产品吗？
2. **产品层** — 能看出在什么场景使用吗？
3. **行为层** — 能看到谁在用、怎么用吗？
4. **动机层** — 能理解为什么需要它吗？
5. **结果层** — 能感受到使用后的效果/结果吗？
6. **一致性** — 整套图的视觉风格是否统一？

### 12.8 阶段三补充：品类知识引擎

每个品类沉淀一份"品类宝典"：最优方案、禁区、平台规范。新项目自动调取匹配的品类知识。

### 12.9 阶段四补充：趋势预测引擎详细逻辑

```
每周自动运行：
  → 对比"12 个月历史趋势曲线" vs "最近 2 周数据"
  → 发现显著偏移（如某品类白底占比 30% → 55%，连续 3 周上升）
  → 自动判定"趋势转向"（连续 3 周偏移 > 15% 触发）
  → 置信度 > 80%：直接生成新方案 + 通知客户 + 排入 A/B 队列
  → 置信度 50-80%：生成建议 + 标记"建议关注"
  → A/B 完成后结果自动回流 → 更新品类库 + LoRA 参数
```

### 12.10 阶段四补充：L5 自主决策标志

**核心判定标准**：老板不在一周内，系统仍持续运转（自动发现趋势 → 自动出方案 → 自动测试 → 自动沉淀）。
